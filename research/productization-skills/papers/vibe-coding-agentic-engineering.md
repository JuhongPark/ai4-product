# Vibe Coding → Agentic Engineering: The 2026 Paradigm Reframe

> **Date:** 2026-04-21
> **Scope:** Paradigm origin (Karpathy, early 2025), terminology evolution, limits

---

## 1. Summary

"Vibe coding" — coined by Andrej Karpathy in early 2025 — describes AI-assisted development where the developer steers *intent, taste, and architecture* rather than writing line-by-line code. By late 2025 Karpathy himself suggested **"agentic engineering"** as a more accurate name for where the practice had landed.

The terminology shift reflects a sobering — from "vibes are enough" to "AI agents need engineering discipline."

---

## 2. Paradigm Shift

| Dimension | Traditional coding | Vibe coding / Agentic engineering |
|---|---|---|
| Primary output | Source code lines | Intent specifications |
| Review loop | Code review | Prompt iteration + output review |
| Skill emphasis | Syntax, idioms, patterns | Taste, architecture, prompt craft |
| Correctness gate | Tests, linters | Same + AI-generated test suite |
| Team shape | Mostly engineers | Founders, PMs, designers co-build |

---

## 3. Adoption (2026)

- **41%** of global code is AI-generated
- **72%** of developers use AI coding tools daily
- **92%** US developer daily usage
- **78%** of organizations integrated AI into core dev workflows
- AI-savvy professionals earn **40% salary premium** vs. peers

---

## 4. The Founder Productization Effect

Vibe coding + agentic AI are "killing the old startup model of dev teams, big funding, and slow builds" — founders can take an idea to working product in days.

Examples:
- **Lovable**: $20M ARR in 2 months — built by non-technical founders
- **v0 users**: 6M+ — many are PMs and designers, not engineers
- **Indie hacker trend**: Solo founders shipping full SaaS from prompts

This represents the most significant productization democratization since no-code (Bubble/Webflow era) but with **full-stack code output**, not opaque visual runtimes.

---

## 5. Why "Agentic Engineering" Replaced "Vibe Coding"

Karpathy's later framing acknowledges real failure modes:

- **AI-generated code 1.7x more likely to have major issues** (logic errors)
- **2.74x more prone to security vulnerabilities**
- Non-engineer "vibe coders" ship production apps without auth, rate-limiting, or security review
- Prompt-driven output does not substitute for system-level reasoning

The "engineering" in "agentic engineering" insists on retaining disciplined practices: testing, review, architecture, security — even when the code is AI-generated.

---

## 6. The Reality Check

Per The New Stack (2026) and industry consensus:

> "Vibe coding works best as an **exploration layer**, not a replacement for engineering discipline — it's a way to surface intent quickly, not a shortcut around responsibility."

This matches the broader pattern established in the repo's [research/cross-cutting/papers/ai-full-automation-reality.md](../../cross-cutting/papers/ai-full-automation-reality.md): **AI excels at execution, not judgment**. Vibe coding concentrates this phenomenon at the individual developer scale.

---

## 7. Security Implications

Dev.to / Royex / multiple 2026 analyses document new security classes:

- **Prompt-injected code** — LLM generates code that executes malicious prompts
- **Dependency hallucination** — LLM imports non-existent packages; attackers register those names
- **Secret leakage** — Vibe coders paste API keys into prompts
- **Auth bypass** — Generated code skips common auth checks in favor of "works for the happy path"

2026 emergence of "vibe-coded app security review" as a consulting service suggests market recognition.

---

## 8. Research Gaps
